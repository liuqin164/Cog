# Web plugin phase 1 — pi-web-access deep read

This is the learning-graph entry for #225. The source is `pi-web-access@0.47.0` as it sat in the
removed shell dependency tree, read after #224 landed. The shipped shape is
`shell/src/plugins/web.ts`; this note records what was adopted, adapted and skipped, so phase 2
does not re-derive it.

## Adopt

- **Three tools, not one.** `web_search` returns sources, `web_fetch` returns one page, and
  `web_recall` reads the cache by `responseId`. The split keeps each schema small and lets the
  model fetch only what it needs (`mcp-tool-definitions.ts`).
- **`responseId` + `offset`/`limit` + `findText`.** A long body is cached, the first 30k
  characters are returned inline, and the continuation line names the next offset. `findText`
  returns bounded passages instead of paging (`content-find.ts`, `web-tool-core.ts:617-636`).
  Our continuation line uses the same words a model can act on: `Showing characters X-Y of N`.
- **One-hour TTL, on disk.** Pi stores results under a private cache directory and prunes expired
  entries on write (`storage.ts:9`, `:235-292`). We use `<dataDir>/web-cache` at 0700/0600, prune on
  write and remove one expired entry on read.
- **Backend chain with a free first hop.** Exa's no-key MCP endpoint is the first backend,
  DuckDuckGo's HTML endpoint is the fallback, and either can be disabled
  (`exa.ts:242-335`, `duckduckgo.ts:57-120`). Our chain is strictly sequential: Exa error →
  DuckDuckGo; both errors → one structured `search_failed` naming both.
- **Readability → Markdown.** `linkedom` parses the HTML, `@mozilla/readability` selects the
  article, `turndown` renders it as Markdown (`extract.ts:1523-1583`). We keep that pipeline and
  drop Pi's extra fallbacks (see below).
- **SSRF preflight and per-hop revalidation.** Only http/https, no embedded credentials, resolve
  every address and reject loopback/private/link-local/reserved ranges, follow redirects manually
  and revalidate each hop, with a redirect cap (`ssrf-protection.ts:232-332`).

## Adapt

- **One query, one URL.** Pi accepts `queries[]`, `urls[]`, domain/recency filters, categories and
  a provider matrix. Phase 1 takes `query`/`url` plus `numResults`; the model varies queries itself.
- **Plain text instead of Pi's structured content.** Pi carries `structuredContent`, `details`,
  images and annotations. We return text with stable error codes (`ssrf_blocked`,
  `extract_failed`, `cache_expired`, ...), because the shell's tool contract is text-first.
- **Config is a plugin section, not a search-provider file.** `<dataDir>/web.json` has two booleans;
  a missing file means both are on, and an unreadable file/field names itself. Pi's
  `web-search.json` carries keys, proxies, user agents, domain policy and per-provider settings.
- **HTML only, and it says so.** Pi falls back to Jina Reader, RSC extraction, Defuddle and PDF
  extraction. Phase 1 returns `unsupported_content_type` for non-HTML and `extract_failed` for a
  JavaScript shell; the tool description and error both say this is a fetch, not a browser.
- **No API-key path.** Pi prefers an Exa API key and falls back to the free MCP endpoint. Phase 1
  ships only the free endpoint; rate limiting surfaces as `exa_rate_limited` and falls through to
  DuckDuckGo.
- **No session journal / holders / activity monitor.** Pi keeps per-session holders and restores
  results from the transcript (`storage.ts:512-560`). The shell's cache is a TTL directory; a
  restart loses nothing that is still inside the hour, and an expired id names itself.
- **No proxy, curl transport, cookies or custom user agent.** The shell uses its own `fetch` with a
  fixed identification string.

## Skip

- Executing JavaScript, browser automation, Chrome cookie import, authenticated fetches.
- PDF extraction, GitHub repo/issue/PR special cases, YouTube/video understanding, image handling.
- The provider matrix (Brave, Perplexity, Tavily, Firecrawl, Jina, SERP APIs, ...), `source_check`,
  query rewriting, answer modes, curator and prompt workflows.
- Pi's `p-limit` concurrency, rate-limit pacing state and result holder counts: phase 1 is
  sequential and bounded by one tool call.

## Phase 2 openings

The seam that is deliberately left open is the content-type check in `web_fetch`: a PDF branch or a
GitHub branch can be added before extraction without changing the search/cache contract. The
search seam is the two `enabled` flags; a third backend is another branch in the same chain, not a
new tool.
